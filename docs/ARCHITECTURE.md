# Устройство проекта

Технический разбор: что как устроено внутри и почему принято именно так.
Инструкция по установке и игре — в [README](../README.md).

Платформа коротких интерактивных тренировок с геймификацией. Точка входа —
Learning Hub (`/learn`), из которого открываются направления обучения.

| Направление | Маршрут | Состояние |
| --- | --- | --- |
| 🌍 География | `/` | работает |
| 🚩 Флаги | `/play/flag` | работает |
| ➕ Математика | `/math` | сложение работает, остальные действия — «Скоро» |
| 🇬🇧 English | `/english` | 400 слов, три типа квизов, озвучка |
| 🇨🇳 中文 | `/chinese` | 698 иероглифов, пять типов квизов, тоны |
| ♟️ Шахматы | `/chess` | 1000 задач «мат в 1», разбор попыток |
| 🫀 Анатомия | `/anatomy` | органы → кости → мышцы, три навыка на структуру |

Каждое направление — отдельный модуль со своими данными, логикой и
компонентами (`src/modules/*`). Общими остаются профиль, XP, серии,
достижения, лидерборд, навигация и тема. Единая учебная петля для всех
направлений: **Learn → Practice → Test → Master → Compete**.

## География и флаги

Интерактивный 3D-глобус, 194 страны и интервальное повторение, которое само
возвращает то, что пользователь забывает.

Это MVP ядра продукта: работающий цикл «глобус → задание → прогресс → возврат к
забытому». Остальные режимы из продуктовой концепции надстраиваются поверх той же
основы (см. «Что дальше»).

| --- | --- |
| `npm run dev` | режим разработки, http://localhost:3000 |
| `npm run build` / `npm start` | продакшен-сборка и сервер |
| `npm test` | тесты движка повторений и целостности датасетов |

закоммичен, чтобы приложение работало офлайн и не ходило за справочниками.

## Что уже работает

**Глобус.** `react-globe.gl` поверх three.js, контуры 165 стран из Natural Earth;
29 микрогосударств без полигонов показаны точками, так что кликабельны все 194.
Наведение подсвечивает страну, клик открывает карточку с флагом, столицей,
континентом и уровнем освоения. Камера плавно перелетает к выбранной стране или
континенту.

**Игровые режимы** (`/play/<mode>`):

- `flag` — угадай страну по флагу;
- `reverse` — найди флаг названной страны;
- `globe` — найди страну на вращающемся глобусе;
- `capital` — столицы в обе стороны (страна → столица и столица → страна);
- `outline` — угадай страну по изолированному контуру (SVG из GeoJSON, без
  масштаба и подписей; в детском режиме — 3 варианта и подсказка континента);
- `train` — скрытый режим персональной тренировки одной страны
  (`/play/train?country=KZ&skill=outlineToCountry`).

Варианты ответа подбираются не случайно: сначала то, что пользователь уже путал
с этой страной, затем визуально похожие флаги из `src/data/confusables.ts`, затем
соседи по континенту. Именно поэтому Румыния приходит вместе с Чадом, а Австралия
с Новой Зеландией.

**Навыки.** Прогресс страны хранится не одним числом, а по шести независимым
навыкам: флаг → страна, страна → флаг, столица, столица → страна, расположение
на глобусе, контур. Карточка SRS привязана к паре `код страны : навык`
(`KZ:outlineToCountry`). Общее освоение — взвешенная сумма (веса в
`src/lib/skills.ts`); для стран без контура вес контура перераспределяется.
Шесть уровней на навык: не изучалось → знакомство → изучается → запоминается →
уверенное знание → освоено.

**Интервальное повторение.** SM-2 с фазой заучивания (7 минут → час → сутки →
дальше по фактору лёгкости). Ошибка сбрасывает прогресс карточки и возвращает
её в ближайшие минуты. Оценка учитывает скорость ответа и подсказки (ответ с
подсказкой не получает высший балл).

**Профили.** Несколько локальных профилей на устройстве (создание,
переключение, переименование, удаление, гость). Прогресс каждого профиля
полностью независим; последний активный запоминается. Меню — в блоке профиля
в шапке. Старый прогресс v1 автоматически мигрирует в профиль «Игрок»
(`src/lib/migrate.ts`, покрыто тестами).

**Персональный подбор заданий.** Сессия собирается по приоритету: просроченные
повторения → пары из личной путаницы → слабые навыки → незатронутые навыки
знакомых стран → новые страны → контрольное повторение. Путаница хранится в
разрезе навыка: флаги Румынии и Чада можно путать, а их контуры — нет.

**Карточка страны.** Клик по стране на глобусе (главная и `/progress`)
открывает карточку: общее освоение, прогресс каждого навыка, даты следующих
повторений, с чем путаете, кнопки «Тренировать» и тренировки слабого навыка.

**Разбор путаницы.** `/progress` показывает путаемые пары с указанием навыка и
запускает сравнительную тренировку (`/play/flag?pair=RO,TD`).

**Озвучка.** Названия стран и столиц произносятся через встроенный в браузер
синтез речи — без бэкенда и ключей.

**Возрастные режимы.** Малышам 5+ показывается минимум текста, школьникам —
площадь и языки, взрослым — ещё валюта, регион и число соседей.

Образовательный прогресс лежит в `localStorage` (zustand `persist`).

**Соревнования (этап 1).** Раздел `/leaderboard`: серверные аккаунты с уникальным
никнеймом, Skill Score (считается на сервере из сырых счётчиков карточек —
формула в `src/lib/competitive/config.ts`), All-time лидерборд с пагинацией и
«вашей позицией», друзья (заявки/принятие/блокировка) с рейтингом среди друзей,
личные рекорды (Answer Streak ≠ Daily Streak, лучшие сессии по режимам),
обезличенная мировая статистика с «самыми сложными» странами (порог ≥ 100
ответов). Бэкенд — Next Route Handlers + SQLite (`node:sqlite`, файл
`data/mapapp.db`); схема включает таблицы дуэлей и Battle Royale для этапов 2–3.
Три раздельные метрики: Skill Score — знания, XP — активность, ELO — только
соревнования (появится с дуэлями).

## Математика

`/math` → `/math/addition` → `/math/addition/{single|double|triple}`.

**Генерация.** Примеры создаются на лету, тысячи заготовок нигде не хранятся
(`src/modules/mathematics/generator.ts`). Случайность управляемая: сложность
задаётся числом переносов через разряд — без переноса, один перенос, два и
более. Пользователь видит только три уровня (однозначные / двузначные /
трёхзначные), а подсложность подбирает алгоритм по текущему освоению: новичку
почти только лёгкие примеры, освоившему — с несколькими переносами. Внутри
сессии одинаковые пары не повторяются.

**Проверка ответа.** Правильный ответ не хранится в состоянии UI: в компонент
уходит `MathTask` без поля `answer`, а проверка пересчитывает сумму из
операндов. После сессии ответы уходят на `/api/math/sync`, где сервер заново
вычисляет `a + b` и **игнорирует присланный клиентом вердикт**; операнды вне
диапазона уровня отбрасываются, время ответа клампится, ответы быстрее 150 мс
помечаются подозрительными, время записи ставит сервер.

**Ввод.** Число + Enter. Enter же листает дальше после разбора ошибки; есть и
кнопка OK для тач-устройств. Верный ответ — автопереход через 0,7 с, ошибка —
показ правильного ответа и автопереход через 3 с.

**Ошибки.** Каждая ошибка запоминается (пример, ответ пользователя, время).
После сессии — список «Ваши ошибки» и кнопка «Повторить ошибки»; те же примеры
доступны с экрана уровня (`?mistakes=1`). Решённый верно пример уходит из
очереди повторения.

**Освоение.** Не «решил 100 задач = выучил»: mastery = взвешенная сумма
(точность 0.6, объём 0.25, скорость 0.15), **умноженная на точность** — она
работает воротами. Стадии: Изучение → Практика → Уверенно → Освоено.
Цели по уровням (100 / 1000 / 500) и все веса лежат в
`src/modules/mathematics/config.ts` и меняются без правки компонентов.

## English

`/english` → `/english/play` (+ `?mode=mistakes` и `?mode=review`),
подробная статистика — `/english/progress`.

**Словарь.** 400 слов: 300 существительных по 16 категориям и 100 глаголов
(`src/modules/english/data/*.ts`). Формат строки компактный —
`[id, эмодзи, перевод, категория, сложность]`, расширение базы до 1000+ слов
не требует изменений в коде. Изображение слова сейчас — эмодзи; поле `image`
зарезервировано под локальный файл `/english/images/<id>.webp`, компонент
`WordVisual` покажет картинку сразу, как только файл появится. Внешние CDN не
используются. Тест требует **уникальности эмодзи** во всей базе: иначе два
слова были бы неотличимы на картинке.

**Три типа заданий** (печатать ничего не нужно): картинка → слово, слово →
картинка, звук → картинка с кнопкой повтора 🔊.

**Озвучка.** Нажатие на *любой* вариант немедленно произносит выбранное слово —
верное оно или нет, так что каждый вариант является маленьким уроком
произношения. После ошибки следом проговаривается правильное слово. Общий
модуль `src/lib/speech.ts`; браузерный синтез позже меняется на записанные
аудиофайлы без правки вызовов.

**Адаптивность.** Сессия из 10 вопросов собирается не случайно: сначала слова
с недавними ошибками, затем просроченные повторения, затем персональные
путаемые пары, затем новые слова от простых к сложным. Матрица путаницы
записывается в обе стороны (apple ↔ orange), и двойник специально возвращается
в варианты ответа — та же механика, что у флагов. Варианты всегда одного типа:
рядом с глаголом стоят глаголы. Режимы открываются по мере освоения слова:
сначала узнавание картинки, с 30% — обратное задание, с 55% — только на слух.

**SRS общий с флагами.** Движок SM-2 вынесен в `reviewSrs`/`SrsState`
(`src/lib/srs.ts`) и используется и странами, и словами — один алгоритм
повторения на всю платформу.

## 中文 (Chinese)

`/chinese` → `/chinese/play` (+ `?mode=mistakes`, `?mode=review`), подробная
статистика — `/chinese/progress`.

**汉字 first.** Единица обучения — один иероглиф, а не слово: 人 → rén →
«человек». Слова, фразы и грамматика сознательно отложены до следующих этапов.

**База — 698 знаков** в порядке изучения: сначала числа, человек, природа и
тело, затем частотные служебные и абстрактные. Строка компактная —
`['你', 'nǐ', 'ты', 'you', 'people']`; номер тона **не хранится**, а выводится
из диакритики (`pinyin.ts`), поэтому расхождение «значок ≠ поле tone»
невозможно по конструкции. Тест проверяет, что каждый id — ровно один
CJK-символ, дублей нет, а пиньинь записан по правилам постановки тона
(`applyTone(stripTone(p), toneOf(p)) === p`) — именно он поймал в черновике
плейсхолдеры и составные слова.

**Четыре независимых навыка на знак:** узнавание иероглифа, чтение (пиньинь),
значение, восприятие на слух. У каждого свой SRS, поэтому система видит
«узнаёт 你 глазами, но не понимает на слух» и добирает слабый навык.
Знак считается выученным, когда хотя бы два навыка дошли до уровня «узнаёт».

**Пять режимов:** 汉字 → пиньинь, 汉字 → значение, пиньинь → 汉字,
звук → 汉字, звук → пиньинь. Открываются по мере освоения: сначала чтение и
значение, с 30% — обратное задание, с 55% — только на слух.

**Тоны.** Неправильные варианты пиньиня строятся из тоновых двойников того же
слога (nǐ / nì / ní / nī) — в мандарине это и есть главная трудность.
Путаница хранится **двумя матрицами**: иероглифов (你 ↔ 他) и произношений
(mā ↔ má), и обе возвращают двойников в будущие задания.

**Озвучка.** Нажатие на любой вариант немедленно произносит его, верный он или
нет; после ошибки следом проговаривается правильный ответ. Синтез читает 汉字
с правильным тоном, а латиницу — нет, поэтому для варианта-пиньиня ищется
иероглиф с тем же чтением (`characterForPinyin`).

**Постепенное открытие.** Пул растёт тирами 20 → 50 → 100 → 200 → 350 → 500 →
698: следующий набор открывается, когда освоено 70% текущего.

## ♟️ Шахматы

`/chess` → `/chess/play`, родительская статистика — `/chess/progress`.

Это не игра против компьютера и не клон Chess.com, а тренажёр мышления:
только задачи «мат в 1 ход».

**База — 1000 задач, сгенерированных и проверенных движком.** Позиции не
набирались руками: `scripts/generate-chess-puzzles.mjs` расставляет фигуры по
профилям и оставляет только те, что прошли chess.js: FEN корректен, ни одна
сторона не под шахом до хода, мата/пата ещё нет, и существует **ровно один**
ход, ставящий мат. Тест перепроверяет всю базу целиком при каждом прогоне.

**Три уровня различаются по существу**, а не по месту в отсортированном списке.
Сложность считается по абсолютной шкале: густота доски, число легальных ходов,
количество ходов с шахом, но без мата (ложные следы), и «жертвенность» —
можно ли побить матующую фигуру. Квоты 300 / 350 / 350 не дают густым профилям
забить базу:

| Уровень | Фигур | Ходов | Ложных шахов |
| --- | --- | --- | --- |
| Простые | 8.0 | 27 | 1.0 |
| Средние | 10.8 | 37 | 2.3 |
| Сложные | 14.2 | 47 | 5.3 |

Уровень выбирается на `/chess` (`/chess/play?level=3`) — без этого сессия
всегда выдавала бы начало базы, то есть самые лёгкие позиции.

**Никаких подсказок.** Доска не подсвечивает возможные ходы, не рисует стрелок
и не показывает направления — понять, куда ходит фигура, часть задачи.
Подсвечивается только выбранная фигура и, уже после ответа, клетки попытки.

**Три исхода хода** (`engine.ts`, обёртка над chess.js): невозможный ход,
легальный но не мат, и мат. Ошибка **не закрывает задачу**: позиция остаётся,
ребёнок ищет дальше. XP за ошибки не отнимается — их вообще нельзя потерять.

**Сохраняется весь ход мысли,** а не флажок «решено». По каждой попытке:
номер, откуда и куда, фигура, запись хода, легальность, результат, шах, время
от начала задачи и **пауза с предыдущей попытки** — по ней видно, думал ребёнок
или перебирал наугад. Отдельно считается `solvedFirstTry`.

**Детский и родительский экраны разделены.** Ребёнку — доска, таймер и
ободряющие цифры. Родителю на `/chess/progress` — точность с первой попытки,
среднее и **медианное** время (пара долгих задач иначе перекашивает среднее),
самая быстрая и самая долгая, разбивка попыток на невозможные / без мата /
маты, и полная история любой задачи по клику.

## 🫀 Анатомия

`/anatomy` (путь обучения) → `/anatomy/play?region=…`, прогресс —
`/anatomy/progress`.

**Путь: органы → кости → мышцы.** Следующая система открывается, когда освоено
60% предыдущей. Кости изучаются **по регионам** (череп, рука, нога, туловище),
а не «весь скелет сразу»; полный скелет открывается после 75% костей и служит
итоговой проверкой.

**Три независимых навыка на структуру** — узнавание, название, расположение.
У каждого свой SRS, поэтому видно «знает термин, но не понимает, где это
находится». Три типа заданий ровно соответствуют навыкам: «Что это?»
(структура → название), «Найди изображение» (название → схема), «Покажи на
теле» (клик прямо по нужной области).

### Иллюстрации

Нарисованных вручную схем в модуле нет: всё, что видит ребёнок, — настоящие
медицинские иллюстрации из учебника OpenStax «Anatomy and Physiology 2e»
(Rice University), лицензия **CC BY-NC-SA 4.0**.

Два слоя:

1. **Базовая иллюстрация региона** (`public/anatomy/base/*.webp`) — тело с
   органами, череп с цветовой заливкой костей, скелет, рука, нога, мышцы.
   Восемь картинок на семь экранов обучения плюс полный скелет.
2. **Зоны структур** (`data/hotspots.ts`) — прозрачные эллипсы поверх картинки
   в процентах от кадра. Это единственный вектор в модуле, и он ничего не
   рисует: пока не нажали и не подсвечиваем, слой невидим. Без него не
   работают ни подсветка одной кости, ни режим «Покажи на теле».
   Попадание считается по ближайшей зоне (`pickHotspot`), поэтому мелкие кости
   на полном скелете тоже нажимаются, а мёртвых зон между ними нет.

Плюс **25 отдельных рисунков структур** (`public/anatomy/*.webp`) — крупный
план органа или кости для вопросов «Что это?» и «Найди изображение». Там, где
чистого отдельного рисунка в учебнике нет (кости черепа по одной, плечевая,
лучевая, локтевая, печень с соседями, надколенник), показывается базовая
иллюстрация региона с обведённой структурой.

Важное следствие лицензии: **NC — только некоммерческое использование**, а
**SA** обязывает распространять переработанные рисунки под той же лицензией.
Если приложение станет платным, иллюстрации придётся заменить. Указание
источника стоит на всех экранах модуля (`components/ImageCredit.tsx`).

Как всё это готовится (учебник в репозиторий не кладётся, лежит в
`assets-src/`, которая в `.gitignore`):

```
node scripts/pdf-figures.mjs <pdf>          индекс подписей → assets-src/figures-index.json
node scripts/pdf-images.mjs <pdf> "253,317" выгрузка встроенных картинок в исходном разрешении
npm run assets:anatomy                      базы + отдельные структуры + оба манифеста
```

Рамки обрезки и белые маски (закрыть подпись, лежащую на белом фоне) заданы
долями в `scripts/anatomy-crops.mjs`. Подгонка — двумя предпросмотрами, оба
рисуют сетку с шагом 5 %:

```
CELL=1150 COLUMNS=2 node scripts/anatomy-preview.mjs femur,tibia   рамка поверх страницы учебника
node scripts/anatomy-hotspots-preview.mjs skull                    зоны поверх готовой базы
```

Границы выбраны так, чтобы английские подписи учебника остались за кадром:
модуль русскоязычный, и подпись на картинке подсказывала бы ответ. По той же
причине в «Найди изображение» отдельные рисунки показываются, только если они
есть у **всех** вариантов.

Числа зон привязаны к кадру: поменяли `crop` — перечитайте зоны предпросмотром,
иначе они поедут. Тесты проверяют, что у каждой структуры есть зона в своём
регионе, что зоны не вылезают за кадр, не совпадают центрами и что клик в
центр зоны возвращает именно свою структуру.

Полный скелет — итоговая проверка, и на нём спрашиваются только крупные кости:
отдельные кости черепа, лучевая и локтевая в масштабе всей фигуры занимают
считаные пиксели, попадание по ним было бы вопросом меткости, а не знания. Их
спрашивают в своих регионах — «Череп» и «Рука».

Эмодзи не используются нигде: тест проверяет и названия, и пояснения.

Озвучки нет — в отличие от English и 中文 здесь она не основа обучения.

## Устройство

```
src/modules/registry.ts        реестр направлений — из него рисуется Learning Hub
src/modules/anatomy/           модуль анатомии: каталог структур, векторные
                               схемы регионов, mastery (3 навыка), session
src/modules/chess/             модуль шахмат: engine (chess.js), progress
                               (история попыток), components (доска без подсказок)
src/modules/chinese/           модуль китайского: data/, pinyin (тоны), characters,
                               config, mastery (4 навыка), progress, session
src/modules/english/           модуль английского: data/, words, config, mastery,
                               progress (SRS + confusion), session, components
src/modules/mathematics/       модуль математики: config, types, generator,
                               mastery, progress, components/MathSession
scripts/                генераторы данных (запускаются вручную, не при сборке)
src/data/               countries.ts (сгенерирован), capitals.ru.json, confusables.ts
src/lib/types.ts        доменные типы (Country, CountrySkill, ReviewCard, UserProfile)
src/lib/skills.ts       навыки: веса, уровни, проценты, общее освоение страны
src/lib/srs.ts          SM-2 — чистые функции, покрыты тестами
src/lib/progress.ts     чистый слой данных профиля: applyAnswer, достижения, путаница
src/lib/quiz.ts         персональная сессия, outline-варианты, тренировки
src/lib/migrate.ts      миграция persisted store v1 → v2 (профили)
src/lib/outlines.ts     GeoJSON → SVG-путь (контуры, мини-карта), чистые функции
src/lib/store.ts        zustand: тонкая обёртка над progress.ts + профили
src/components/         GlobeView, PlaySession, OutlineShape, ProfileMenu и UI
public/flags, /textures, /data   локальные ассеты
```

Хранение: один ключ `geoquest-progress` в localStorage (zustand persist,
version 2): `{ profiles: Record<id, UserProfile>, activeProfileId, data:
Record<id, ProfileData> }`. Вся логика изменения данных — чистые функции в
`progress.ts`/`migrate.ts`, поэтому тестируется в node без браузера.

Данные о странах собраны из пакета `world-countries` скриптом
`scripts/generate-countries.mjs` и закоммичены как обычный TS-модуль: в рантайме
приложение никуда не ходит за справочниками. Русские столицы ведутся вручную в
`src/data/capitals.ru.json`. Флаги и текстуры Земли скачаны в `public/` —
приложение работает офлайн.

`src/data/countries.ts` править руками нельзя, он перегенерируется. Правки идут в
`capitals.ru.json` или в `NAME_OVERRIDES` внутри скрипта.

## Что дальше

Не входило и требует отдельной работы:

- математика: вычитание, умножение, деление (структура уровней и генератор
  готовы к переиспользованию), явный выбор подсложности;
- English: правописание, предложения, грамматика и говорение — надстройка над
  готовым словарным фундаментом; записанные аудиофайлы вместо браузерного TTS
  и настоящие иллюстрации вместо эмодзи;
- 中文: сочетания иероглифов и двусложные слова (你 + 好 → 你好), фразы,
  предложения, порядок черт и запись от руки; записи носителей вместо TTS;
- шахматы: мат в 2 хода, подсказки (сначала атакующая фигура, потом поле),
  тактические темы (вилки, связки), адаптивный подбор задач по слабым местам;
- анатомия: отдельные крупные планы для 12 структур, которых нет в учебнике
  изолированно; нервная, кровеносная и дыхательная системы, органы чувств,
  ткани — добавляются как новый `system` + регион с базовой картинкой и зонами;
- режимы «собери флаг» и «испытание на время»;
- мультиплеер «битва игроков» — нужен бэкенд и WebSocket;
- серверные аккаунты и синхронизация (структура профилей к этому готова:
  прогресс уже привязан к profileId), freemium, школьные классы;
- AI-наставник: подбор заданий детерминированный, персонажа нет;
- произношение на иностранных языках и распознавание речи с микрофона;
- новые навыки (языки, валюты, соседи) — добавляются расширением
  `CountrySkill` и `SKILL_META`.

Известные ограничения:

- Natural Earth 110m не содержит контуров 29 микрогосударств (AD, AG, BB, BH,
  CV, DM, FM, GD, KI, KM, KN, LC, LI, MC, MH, MT, MU, MV, NR, PW, SC, SG, SM,
  ST, TO, TV, VA, VC, WS) — на глобусе они показаны точками, из контурного
  режима исключены, вес навыка «контур» у них перераспределён;
- похожесть контуров для неправильных вариантов — эвристика (континент,
  сопоставимая площадь, островной характер), а не сравнение геометрии;
- v1-статистика правильных/неправильных ответов хранилась на стране целиком —
  при миграции счётчики карточек навыков начинаются с нуля (SM-2-параметры
  сохраняются);
- столица Боливии указана как Сукре, Шри-Ланки — Коломбо, по данным источника.
